The 12 Architecture Rules Cheatsheet

1. Zero Singletons Pass dependencies through constructors or Service Locator. Never use GameManager.Instance.
Avoid: Player.Instance.TakeDamage()
2. Memory Object Pooling Pre-allocate bullets, VFX, and enemies. Never Instantiate() or Destroy() in update loops.
Avoid: Instantiate(bulletPrefab, pos, rot)
3. Explicit State Machines Game state, player animations, and UI screens must be discrete enums with enter/exit hooks.
Use: enum State { Idle, Run, Attack }
4. Zero Hot-Path GC Allocations No LINQ (.Where, .ToList), string concatenation (+), or new T[] inside Update() or Tick().
Avoid: "Score: " + score (in Update)
5. Decoupled Event Bus Use decoupled listeners for damage, inventory, and audio triggers without tight coupling.
Use: Events.OnPlayerDied?.Invoke()
6. Frame-Rate Decoupled Physics All movement and collisions use fixed delta time. Never multiply variable dt in fixed logic.
Use: Time.fixedDeltaTime in FixedUpdate

## Agent Work Crew Roles
1. Agent 1 (Combat Core): /Scripts/Gameplay/Combat/ & /Scripts/Gameplay/Systems/

## Non-Negotiable Guardrails (Ponytail Philosophy)
- RULE 1: Never create extra wrapper classes or factory managers (7-Rung Ladder).
- RULE 2: Keep tick math (60Hz) decoupled from MonoBehaviour Update visual interpolation.
- RULE 3: Save monuments write to disk WITHOUT respawning monsters. Rest monument explicitly repopulates.
